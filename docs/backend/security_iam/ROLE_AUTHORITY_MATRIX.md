# Role Authority Matrix (IAM & RBAC Governance)

Authoritative specification of every role across `SELF`, `ORG`, `INSTITUTION`, and `PLATFORM` scopes in FlexBridge 1.4 (`role_catalog` + scoped grant tables). Every mutating action is enforced server-side inside PostgreSQL transactions (`app/api/dependencies.py`, `app/services/authority.py`, `app/services/platform_admin.py`), never by UI checks or client-supplied headers.

## 2. Initial Super Admin Bootstrap Rule

Because PostgreSQL enforces `chk_platform_grant_not_self CHECK (granted_by_id <> user_id)` and `granted_by_id NOT NULL`, `expires_at NOT NULL` on `platform_role_grants`:

1. **System Authority Anchor (`00000000-0000-0000-0000-000000000001`)**:
   - The CLI `backend/scripts/bootstrap_super_admin.py` creates or reuses a dedicated non-login anchor record in `users`:
     - `id = '00000000-0000-0000-0000-000000000001'`
     - `display_name = 'FlexBridge System Authority'`
     - `status = 'LIMITED'`
     - `password_hash = None`
   - Because `status = 'LIMITED'` and `password_hash IS NULL`, `auth_service.check_password`, `session_authority`, and `account_authority` always reject login and session checks for this anchor. It can never authenticate as a human operator.
2. **Idempotent Grant & Audit**:
   - Ensures `role_catalog` contains `code = 'ADMIN'`, `scope_kind = 'PLATFORM'`.
   - Inserts a `platform_role_grants` row for the target `ACTIVE` human user with `granted_by_id = '00000000-0000-0000-0000-000000000001'` and `expires_at = now() + interval '<days> days'` (default `3650`, range `1..3650`) only if no active unexpired unrevoked `ADMIN` grant already exists for that user.
   - Emits an immutable `audit_events` entry with `action = 'SUPER_ADMIN_BOOTSTRAPPED'`.
3. **MFA Enforcement After Bootstrap**:
   - `ADMIN` is in `SENSITIVE_ROLES`. Even after receiving the `ADMIN` grant, any `PASSWORD` session is blocked from `/api/v1/operator/*` (`403 MFA_ENROLLMENT_REQUIRED` / `403 MFA_REQUIRED`) until the admin enrolls TOTP (either via `--enroll-totp` during bootstrap or via `/api/v1/me/security`) and authenticates with `assurance = 'MFA'`.
4. **No Hardcoded Secrets**:
   - Passwords are never hardcoded; `--create` reads from `--password-env <ENV_VAR_NAME>` or hidden `getpass` input, and `otpauth://` URIs are printed only when `--enroll-totp` is explicitly requested and no verified TOTP already exists.

## 3. Protected Feature Flags & R2 Scope Guard

Per `app/services/feature_flag_admin.py` and migration `0017_feature_flag_administration`:

- **R1 Enableable Flags** (`category = "R1"`, `mutable = true`, `disable_only = false`):
  - `R1_PART_TIME_JOBS`, `R1_GENERAL_INTERNSHIPS`, `R1_ACADEMIC_INTERNSHIPS`
- **Protected Flags** (`category = "PROTECTED"`, `mutable = false`, `disable_only = true`):
  - `ratings`, `academic_official_export`, `WhatsApp`, `paid_checkout`
  - Read-only alias: `R1_PAID_ORG_PLANS` (`alias_of = "paid_checkout"`)
- **Out-of-Scope R2 Flag** (`category = "R2"`, `mutable = false`, `disable_only = true`):
  - `R2_FREELANCE_MARKETPLACE`

`GET /api/v1/operator/feature-flags` (`API-132`) always returns the exact proof-backed `version` (latest `feature_flag_change_events.version` or `0` for unadministered/legacy rows) matching `PATCH /api/v1/operator/feature-flags/{code}` (`API-121`) `If-Match` expectations. Legacy rows with `enabled = true` and no `PUBLIC` change event still read `enabled = false` (fail-closed).
